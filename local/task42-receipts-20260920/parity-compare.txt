Task 42 kernel-parity comparison: stock vs register-cut variant.

Harness `parity.py` runs once per arm inside the task-42 image with the GPU
exclusive, drives the real serving entry point `apply_exl3_experts`, and saves
each case's fp32 output tensor as `<out>.t<tokens>.s<skew>.pt`.
`cmp.py` then compares the two arms' saved tensors. It is CPU-only and needs no
GPU, so it runs in the same image without touching production:

  ssh nvidia@spark1 'docker run --rm -v ~/t42-window:/out \
      --entrypoint python3 glm53-selfbuild:e3-pipeline-f1s8 /out/cmp.py'

Why this file exists: the first attempt at this step ran the comparison on the
HOST, which has no torch, so it died with ModuleNotFoundError and its numbers
were never retained (see final.log section 3). The result below is a re-run
against the tensors the harness had already saved, on the same image and
revision, with production untouched.

Metric definitions, as implemented in cmp.py (a and b are the two arms' fp32
outputs, elementwise):

  maxabs delta = max |a - b|
  rel maxabs   = max |a - b| / mean |a|      <- normalized, NOT per-element
  nrmse        = rms(a - b) / mean |a|
  bit-exact    = torch.equal(a, b), i.e. the sha256 recorded in the JSONs

The "rel maxabs" scale is mean |a|, so it is not a per-element relative error
and should not be quoted as one.
