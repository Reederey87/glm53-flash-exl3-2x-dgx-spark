FIX 2 - the settle gate is below vLLM's own demand, so the first boot raced a near miss.
  r1: gate PASSED at head 115 GiB / worker 114 GiB, yet vLLM then saw 103.09 GiB
  against a 0.85 x 121.69 = 103.44 GiB requirement and exited 1.
  Raising NEED_GIB cannot fix this: free memory DROPS during the boot (page cache
  from the 21 GB image ship and the weight read), and idle MemFree is only 93-97 GiB.
  fix: bounded retry (MAX_BOOT_ATTEMPTS=3) around start.sh, re-running settle_wait()
  between attempts. Lowering the gate instead would turn a clean pre-check failure
  into a real OOM.
  validated: r2 cleared the same boot on the next attempt (health 200).

FIX 3 - the retry loop reported success when every attempt failed (found by review).
  The loop read `rc=$?` AFTER the completed `if ./start.sh start; then ... fi`.
  An `if` whose condition fails and which has no `else` branch exits 0, so `rc`
  was always 0: after three failed boots the launcher logged the error and then
  exited 0 with production down, hiding the failure from any supervisor.
  fix: capture the status in the `else` branch, where `$?` is the failed
  condition's status.
  Defect class: arrived WITH the retry loop written in this window; the previous
  `exec ./start.sh start` propagated the status correctly, so no earlier shipped
  launcher had it.

  Reproduced on the Mac and on the cluster. Cluster run, retry block extracted
  verbatim from each launcher, driven by a fake start.sh in a scratch temp dir:
