1. Review round 5 on 628833d — CHANGES REQUIRED, four findings
--------------------------------------------------------------

All four were behavioural. Each now has a regression test verified RED against
628833d (15 failed, 30 passed on the pre-fix sources; 708 passed, 1 skipped, 18
subtests after the fix).

F1  prod-start.sh exited BEFORE cleaning up on exhaustion.
    Pre-fix symptom (test_exhaustion_still_cleans_up_the_partial_launch):
      AssertionError: ['start']          <- no `stop` was ever issued
    The last failed attempt's containers stayed up while the log said
    "production left down". They hold unified memory plus the API/master ports,
    which is exactly what makes the next manual start fail. Cleanup now runs
    before the exhaustion decision, so it happens on the final attempt too.

F2  `start.sh preflight` was not read-only.
    (a) the `.env` bootstrap skipped only `validate`, so a missing `.env` was
        written from env.example by every other subcommand — including the
        classifier prod-start.sh depends on. A classifier that mutates state
        also changes its own next answer.
    (b) preflight() ran `mkdir -p "$HF_CACHE_DIR"` and a remote
        `worker_ssh "mkdir -p '$WORKER_CACHE_DIR/hub' ..."`.
    Fixed: the bootstrap computes `_readonly_cmd` from `${1:-start}` and refuses
    for `validate|preflight`; a new `READ_ONLY` flag (set in the `preflight)`
    dispatch arm) guards both mkdirs, testing instead of creating.
    Design note: under READ_ONLY a missing cache only WARNS, because `start`
    would create it — dying there would abort a retry that could still succeed.

F3  `preflight && log "preflight OK"` suppressed errexit.
    A call inside an AND-list disables `set -e` for the whole call, so preflight
    reported success on a failed check.
    Pre-fix symptom (test_dispatch_propagates_a_failure_from_inside_preflight):
      returned 0 and printed REACHED-END
    Pre-fix symptom (test_dispatch_propagates_an_implicit_mid_body_failure):
      returned 0 and printed `LOG: preflight OK`
    Fixed: `preflight` is now called STANDALONE. The two GID table reads also
    carry an explicit `|| die` — a command substitution that printed a usable
    row and THEN returned non-zero was swallowed, so an incomplete check read as
    a pass. Pre-fix symptom:
      assert '|| die' in 'head_table="$(gid_table "$HEAD_CX7_IB")"'

F4  Malformed IPv4 accepted, resolving to a PLAUSIBLE GID.
    Three forms survived `read -a` plus the per-octet loop:
      192.168.177.11.                      -> the worker's address
        (`read -a` drops the empty fifth field, so the 4-field count passed)
      192.168.177.18446744073709551627     -> the worker's address
        (`$((10#$o))` overflowed 64 bits and wrapped to 11)
      192.168.177.11\nignored              -> the worker's address
        (`read` consumed only the first line and discarded the rest)
    A bad HEAD_IP/WORKER_IP in .env would therefore have silently matched the
    wrong fabric address instead of failing closed.
    Fixed: anchored `^[0-9]+\.[0-9]+\.[0-9]+\.[0-9]+$`, then a DIGIT-COUNT bound
    (`${#o} -le 3`) BEFORE any arithmetic so an overflow cannot wrap, then the
    <=255 check. `192.168.177.010` still resolves as decimal 10 (intended).

P3  `MAX_BOOT_ATTEMPTS=bogus` disabled the retry bound entirely, because
    `[ "$attempt" -ge "bogus" ]` is false. Pre-fix symptom: "ran 100". A
    non-numeric or sub-1 value now falls back to 3 with a warning.

22-case standalone matrix over ipv4_mapped_gid (valid addresses, the three
reported forms, and 19 other edge cases) — all 22 behaved as intended.
