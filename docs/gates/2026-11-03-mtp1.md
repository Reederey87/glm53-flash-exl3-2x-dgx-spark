# MTP1 versus incumbent MTP5 — candidate 05 preregistration

Prepared before either arm is measured. This is a future, separate window
after the active Int64 build/test window has ended and the incumbent has been
restored. It does not interrupt that build, select an image, or adopt MTP3.

## Research and source review

[vLLM's speculative-decoding documentation](https://docs.vllm.ai/en/stable/features/speculative_decoding/)
describes a latency/throughput tradeoff rather than a universally best draft
depth. Reducing five draft tokens to one may reduce rejected work and verifier
cost under concurrency, but also reduces accepted tokens per verification.
The completed MTP3 trial motivates measuring the remaining queued fixed-depth
arm; it does not establish an MTP1 result.

Stronger options were reviewed through Exa before preparing the patch:
batch-dependent schedules, acceptance-window adaptation and
[cost-profiled adaptive verification](https://docs.vllm.ai/en/stable/features/speculative_decoding/adaptive_verification/).
The last adds full-graph, attention-backend and draft-logit requirements; its
compatibility with the pinned image and B12X is not established by current
upstream documentation. [Issue 49548](https://github.com/vllm-project/vllm/issues/49548)
reports a dynamic-depth concurrency regression on a different Spark/model
configuration. It warrants a mixed-load gate, not an assumption that this
deployment has that defect. The dynamic-SD documentation URL returned HTTP429
in Exa; the primary issue and exact local source were available.

Reviewed pinned vLLM `8244d1c44348ae8a5bbfc9f1b607021652283ed4`:
`vllm/config/speculative.py` permits positive fixed depth, exposes both
`adaptive_speculative_tokens_window` and
`num_speculative_tokens_per_batch_size`, and distinguishes single/multiple MTP
modules. Reviewed Exllamav3 `generator/draft_confidence.py`: its calibration
requires tested-position labels and burn-in, so confidence adaptation is a
different treatment, not a substitute for this fixed-depth trial. Reviewed
TensorFold GLM `cuda_prefix.zig` and `tools/shared_prefix_load.py`: preserve
complete MTP/recurrent prefix state and distinguish per-stream timing from
full-cell output throughput. The existing prefix smoke and corrected metric
labels carry those checks into this trial. No EXL3 quant or TensorFold server
is introduced.

## Measurement and decision

Use frozen speed harness `05c6023a4b0df380aae5bdb159afab32c1bf516a`, SHA256
`85371429e129aeb62f4f9f28b918d8453eb292267654e0e6d30489e0f4368401`,
with new seed **2026110305** identically in both arms. Measure fresh MTP5
control data in this window; do not reuse the earlier MTP3 trial's control.
Run three repetitions: unique no-cache prefill 8192/16384/32768/65536/131072
at c1/2/4/8, then code/prose/structured decode at the same concurrencies,
200 generated tokens including reasoning, explicit `reasoning_effort=max`,
temperature 0 and the existing discarded warmup per decode cell. Record c8
queueing against cap 4. Expected coverage is 96 measured cells plus 40 warmups
per arm; match prompt hashes, token budgets and settings exactly.

Retain the [MTP3 gate's metric conventions](2026-11-03-mtp3.md): reciprocal
TPOT `(N-1)/(last-first usage update)`, normalized aggregate `sum(N-1)/wall`,
plus separately labeled full-cell and bundle-aware diagnostics. Fixed-budget
reasoning is not completed-answer latency or quality. Report speculative
counter deltas per cell: `1+accepted/drafts` and `accepted/drafted`.

Reject a >2% prefill/decode or draft-acceptance-rate regression in at least
two of three paired repetitions. Require a repeatable >=2% real-task decode
gain outside the control range, with no robust regression elsewhere, to
recommend adoption. Mean acceptance length is diagnostic because its maximum
differs at depths 1 and 5. Effects within the control range are inconclusive.
Both arms must pass API/reasoning/tool and cold/hot prefix smoke, retain the
same KV capacity, and have no corrupt/nonfinite output, CUDA/Xid errors, rank
loss or sustained swapping. Missing/partial/invalid receipts cannot pass.
