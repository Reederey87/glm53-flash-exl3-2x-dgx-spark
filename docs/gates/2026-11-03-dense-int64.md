## Native gate before serving

Require exact installed treatment hashes, matching package inventories and
native SM121 compilation/execution on both GB10s with fresh per-arm caches.
Both arms run bounded A16/blockscaled/MXFP8 correctness and graph suites.
Only the candidate runs the known-overflow high-offset case and its Compute
Sanitizer memcheck: M=4096, N=34816, K=1024, split-K=16, FP32 scratch >8 GiB.
The constant-output oracle and changed-input graph replay must pass. Do not
inject the overflowing case into the known-broken control. Record resource/
spill reports, native artifact identities, graph allocation behavior and all
skips; skipped coverage is not a pass. Any correctness failure prevents serving.

After native qualification, record built image identities before starting a
serving arm. First qualify the rebuilt control against the incumbent so that
dependency drift is not attributed to the kernel patch. The paired serving
gate retains frozen harness `05c6023`, seed 2026110304, explicit max reasoning,
three repetitions of the 8k–128k no-cache ladder and code/prose/structured
200-generated-token decode at concurrency 1/2/4/8. Reject >2% prefill, decode
or draft-acceptance regression in at least two matched repetitions; interpret
control variability. Require all functional/cache/KV controls to pass.

After the window, restore the incumbent through the unit, verify identity,
health and capacity, and re-arm the watchdog. This is a correctness candidate;
neutral speed can qualify only after the native and serving gates pass.
Final adoption requires a separate user decision with receipts.
